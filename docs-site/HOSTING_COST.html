01 The Two Options

Both options run on a dedicated server, meaning nothing else shares it. The only real difference is where the database and files live.

OptionWhat it usesCost
A Recommended Dedicated server for the app, database on Supabase, files on Cloudflare R2. The same setup already running today, just moved to a server nothing else shares. ~$7฿232/mo
B Dedicated server running its own database and its own file storage, no Supabase, no R2 ~$13–14฿430–464/mo

02 Recommendation

Option A. The app itself is light on memory, so a small server is genuinely enough for it. Supabase and Cloudflare R2 are both still free at this site's size, and they already handle the harder parts (backups, serving files worldwide) better than a cheap server could do on its own.

Option B saves nothing and costs more. Running your own database means running your own backups too, and doing that properly (copying them somewhere safe, not just onto the same disk) takes real setup work. For a personal site with modest traffic, that's effort spent solving a problem Option A already has solved for free.

The one reason to still pick Option B: not wanting the database and files to depend on a company's free-tier terms staying the same. Reasonable to want, but it costs more, in both money and setup effort, to get it.

05 Can These Sizes Actually Run It? Checked, not assumed: against the app's own documented memory settings and general server-sizing guidance.

Option A's server (1 GB)

The app's own production settings already cap it at 512 MB of memory (docker-compose.production.yml: NODE_OPTIONS=--max-old-space-size=256, container limit 512m), but that cap is for the app container, not the whole machine. The operating system, the Docker engine itself, and the Caddy reverse proxy in front of it also need memory, and DigitalOcean's own guidance recommends at least 1 GB of RAM to run Docker reliably. A 512 MB server (the $4 plan) would leave next to nothing for that overhead, which is why it's marked "too small" above rather than recommended, even though it's cheaper. The 1 GB plan gives the app its documented 512 MB and leaves roughly the other half for the system around it, which matches DigitalOcean's own floor.

Option B's server (2 GB)

Postgres itself can run in very little memory for a small, low-traffic, single-user database (some guides cite 256 MB as workable with a tuned-down configuration). That's Postgres alone, though. Add the app's own 512 MB and the same OS/Docker overhead from above, and a 1 GB server leaves barely any margin: fine most of the time, but a bad moment for the app and the database to both be doing something at once could tip it into swapping or an out-of-memory restart. A 2 GB server gives each piece real headroom instead of a size that technically starts but stays fragile, which is why it's the pick above rather than the cheaper 1 GB plan.

Neither pick is guesswork: both are sized against the app's own configuration file and DigitalOcean's own minimum-RAM guidance for Docker, not just "smallest available."
