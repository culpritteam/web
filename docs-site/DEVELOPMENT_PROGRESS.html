Development Progress

Status update for "The Culprit," a personal academic website and appointment system.
Period: 2026-07-26 to 2026-08-12 Status: Live Environment: self-hosted VPS

01 Overview

The site is finished and live. Every public page and every admin screen described in the spec is built and working, running in production on a self-hosted server behind Cloudflare. What's left below is smaller follow-up work, not core features.

02 Delivered

AreaWhat it doesStatus
Public site Bio, Research, Publications, Research Groups, Upcoming Events, and Make Appointment, all editable from the admin dashboard. Live
Appointments The admin creates appointments directly. No request/approve workflow, and appointments are never deleted, only marked cancelled. Live
Booking widget Calendly, embedded on the page, with a quick bot check first so it can't be spammed. Live
Admin login Single-admin sign-in protecting every management action. Live
Caching & rate limiting Public pages cached at the server and, on the self-hosted deployment, at Cloudflare's edge too. Login attempts are rate-limited at two layers. Live
Hosting & deployment A GitHub Actions pipeline builds a Docker image and rolls it out to the self-hosted server automatically on every push to main. Live

03 Follow-up Work

ItemNotesStatus
Cloudflare edge purge on save Built and tested, but needs one more credential added to the server before it turns on in production. Until then, edge-cached pages still refresh, just within their normal cache window (5 minutes to 1 hour) instead of instantly. Needs setup
End-to-end tests in CI The Playwright test suite exists and passes, it just isn't run automatically on every push yet. Not wired up
Privacy / data retention policy Appointment records are kept indefinitely today. No policy page or deletion process exists yet. Open question

04 Open Questions

  • Should appointment records eventually be deleted or archived after some amount of time?
  • Should publications be entered by hand going forward, or imported from an existing list (BibTeX, ORCID)?
  • Is the current single-admin model enough long-term, or will a second admin account ever be needed?
