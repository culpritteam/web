02 Deploy Pipeline

Every push to the main branch on GitHub builds the app, checks types, runs the test suite, and applies any database changes. All of that happens before anything goes live, not after. GitHub Actions then builds a Docker image and pushes it to a container registry. The server pulls that image and restarts the container. It never builds anything itself, it only runs what CI already built and tested. If the new container doesn't pass its health check, the pipeline automatically puts the previous version back, so a bad deploy can't take the site down.

03 Cloudflare & Caching

The self-hosted deployment sits behind Cloudflare, which does three things:

  • Caches public pages at the edge. Most visitors get served straight from Cloudflare, never touching the app server or the database. An admin edit clears that cache within a second or two, not after some long wait.
  • Blocks login attack attempts. Too many login tries too fast get stopped before they even reach the server.
  • Runs a quick bot check on the booking page, so the Calendly widget can't get spammed by a script.

None of this needs a paid Cloudflare plan. Everything here runs on the free tier.
